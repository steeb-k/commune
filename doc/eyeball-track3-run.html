Every check here passes the compiler, clippy, the tests and all fifteen of checks-bin, and none of them can judge it. Work top to bottom — the sections are ordered newest first, because the code nobody has looked at is the code most likely to be wrong. What you tick stays in this browser and nowhere else. Mark a failure and you get somewhere to say what happened and to attach a screenshot; Copy report or Save report then gathers them up.

How to run this

Build the fractal-kotlin branch on the Linux desktop as before; the binary must be newer than 840f76be. doc/eyeball-track3-run.html is this file with checkboxes, generated by doc/eyeball-page.py track3 and published at the URL in that page's top comment. Regenerate and republish it whenever this file changes.

The homeserver harness is the desktop ledger's:

testing/local-homeserver.sh up      # or `reset` for a clean slate
testing/local-homeserver.sh verify

Log in as alice — Another Homeserver → localhost:8008. The passwords are alice-is-testing, bob-is-testing, carol-is-testing, admin-is-testing. Bob is the second member of nearly everything and the other end of every two-party check; carol has joined nothing. A second client for bob — a second Commune profile, or Element in a browser — is needed from the sidebar section on, and the calls section needs it on a second machine or device with a camera.

The order is dependency order, not newest first. Everything needs a session, so the session list goes first; the sidebar is what every room check is looked at through; the rest follow what they need. The strings audit's items sit inside the sections they belong to. Calls are last and need the harness in doc/calls.md.

The half worth caring about is the same half as always: the checks phrased as something that should not happen, and the checks of a value that changes while a page is open — a name, a count, a state — because a mirror that is wired once and never updated looks right until then.
